# Mitarbeit an County 13

Kommunikation und Dokumentation erfolgen standardmäßig auf Deutsch.

1. Beschreibe einen Fehler oder Vorschlag in einem Issue. Öffentliche Beiträge enthalten nur freigegebene Inhalte.
2. Erstelle einen kurzen Arbeitsbranch, beispielsweise `feature/dokumentenregister` oder `fix/zugriffspruefung`.
3. Halte Änderungen überschaubar und dokumentiere neue Abhängigkeiten und Konfigurationswerte ohne reale Zugangsdaten.
4. Prüfe das tatsächlich geänderte Verhalten auf einem geeigneten Teststand. Benenne fehlende Prüfungen offen.
5. Öffne einen Pull Request mit Problem, Ergebnis und Prüfnachweisen. Das Projektteam entscheidet über die Aufnahme.

Neue Ideen sind Vorschläge. Öffentliche Lore, internes Teamwissen und Charakterwissen bleiben getrennt. Das Team prüft Kanonänderungen anhand der geschützten Projektquellen.

Keine Spielerexporte, Datenbanksicherungen, Tokens, Passwörter, Lizenzschlüssel, produktiven Konfigurationen oder gekauften Ressourcen hochladen. Fremder Code braucht nachvollziehbare Herkunft und passende Nutzungsrechte.

Das Repository enthält keine allgemeine Freigabe zur Nutzung oder Weiterverteilung der Projektinhalte; siehe `NOTICE.md`.
